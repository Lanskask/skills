# Decision log

| Decision | Reason |
|---|---|
| Output = same HTML layout as codebase-to-course, assets copied into `assets/` | Requirement: a book course must look and feel like a codebase course. Copy (not reference) so the skill works if the sibling moves; `render` never regenerates CSS/JS. `book-extras.css` adds only 6 classes. |
| Lessons are JSON drafts, rendered by script | Reproducibility: a fixed schema is validated identically for any model; the model never writes HTML boilerplate. |
| PyMuPDF + stdlib, dependencies via `uv run --script` (PEP 723) | Requirement/choice: the user chose it. PyMuPDF gives font size/bold flags (heading and term detection) and a PDF outline. Cost: AGPL license. `pdftotext` was not used because it lacks font data. |
| TF-IDF + TextRank written in stdlib | Deterministic across machines and library versions; no numpy/sklearn install. IDF is book-wide so a chapter's keywords are what is distinctive about it. |
| Citations are 1-based PDF page indexes | Printed page labels are unreliable (roman numerals, offsets). Stated in the manifest. |
| Outline ids (`chNN`) are assigned over the whole-book outline before clipping to a scope | Same chapter keeps the same id whether you process pages 1-39 or 11-17 (tested). Not possible for heading/chunk detection; documented in gotchas. |
| Header/footer removal: margin-band lines repeated on ≥ 3 pages; boilerplate only when it is a one-line block repeated on ≥ 30% of pages | First version removed wrapped body lines on the synthetic book (measured), so boilerplate is restricted to standalone lines; every removed pattern is listed in `clean_report.json`. |
| Soft hyphen U+00AD → "-" at extraction | Measured: MuPDF reports every hyphen, even real ones, as U+00AD. Line-end hyphens are then joined by `join_lines`. |
| Quote limit 25 words / 15% of lesson; 12-word shingle copy check (error at 25) | Short, attributed quotes only; paraphrase otherwise (copyright and pedagogy). Thresholds are policy, not measured. |
| Group chat and data-flow animations are not in the book version | They invent dialogue that cannot be checked against pages. Quizzes, tooltips, callouts, cards, steps and source ↔ plain-words blocks (analogue of code ↔ English) cover the mandatory set. |
| `needs_more` instead of an automatic full read | The model decides what to read; the script only flags it and logs the cost, keeping spend visible. |
| Token estimator ≈ 4 chars/token Latin, 2.5 Cyrillic | Model-independent rough estimate; labelled as estimate everywhere. |
| LaTeX: rebuild a draft from the PDF text layer (font size + baseline), no ML OCR | Deterministic, no GPU/PyTorch, free of tokens; correct for simple inline/display formulas in LaTeX-typeset PDFs (tested on a synthetic book only). Wrong for fractions/matrices/scans, so the model verifies against a PNG crop on demand instead of us promising accuracy. |
| Equation images are cropped on demand (`eq --image`), not at `prepare` | A 500-page physics book has thousands of equations; most are never needed. A crop is ~hundreds of tokens when the model views it. |
| Renderer: KaTeX from jsDelivr CDN, `throwOnError: false`, `trust: false`; `book-math.js` only if math is used | KaTeX is small, fast, and has no `\newcommand`/file access. CDN matches the existing Google Fonts dependency; offline the raw TeX stays visible. Vendoring ~1 MB of fonts was not worth it. |
| Math blocks need `origin: book|derived`, a symbol table and a page cite | Keeps "what the book says" separate from what the model derived; satisfies "define each term for a student" and the grounding rule. |
| Formula grounding = distinctive atoms (Greek, `∑∫√`, numbers >= 2 digits) found on the cited page; error below 50%, warning below 80% | Cheap, model-independent check that catches fabricated formulas. Relations like `≈` are excluded because extractors often drop or remap them (measured: false error on the sample). It cannot catch a mistyped formula that shares those atoms. |
| LaTeX check is structural (braces, `\left/\right`, environments, `\frac` arity, unsupported-command list), not a real KaTeX run | No Node dependency; deterministic. The renderer's `throwOnError: false` shows bad source instead of breaking the page. |
| Diagrams are specs rendered to SVG by script (flow, plot), not SVG written by the model | Reproducible across models, validated (ids, edges, expressions), themed with the course CSS, tiny token cost, and no chance of broken or hallucinated drawings. Cost: only two diagram kinds. |
| Plot expressions pass an AST whitelist, ints become floats before eval, builtins removed | The spec comes from an LLM, possibly influenced by book text; no code execution, no huge-integer `9**9**9` hang (tested). |
| Series are distinguished by colour and dash pattern | Measured on the first render: two curves came out the same colour (accent and actor-2 are both teal). Dashes keep them readable in greyscale. |
| Book figures are cropped from the PDF by caption proximity (graphics clusters + inner text), on demand | No ML; works for vector/raster graphics in LaTeX/Word PDFs; fails honestly (validator error) for scans. Personal-study use; not for republishing. |
| Printed-page mapping from margin page numbers, mode of offsets near the range, >= 3 agreeing pages | The user quotes the book's contents (printed numbers); guessing an offset silently would cite the wrong pages. Refuses instead. |
| Ligatures expanded and `¨ ´ ˆ ˜` composed before a vowel in `_normalise`; backtick excluded | Real physics PDFs give `Diﬀusion`, `Schr¨odinger`; keywords/quotes must match. Backtick is common in code listings, so it is not treated as an accent. |
| Problems become `task` blocks: verbatim (<= 120 words, verified on the page) + plain-words restatement; no invented solutions | User requirement: copy problems as tasks, understandable at the course's level. The 120-word cap keeps copying to problem statements; solutions are only given if the book prints them. |
| Output stays in the current folder (user decision); scripts are called by absolute path | The user chose to keep the existing output location. |
| MATH_FONT = CMMI/CMSY/CMEX/CMMIB/CMBSY + AMS + "Math"/Symbol; CMR/CMBX/CMTI/CMSS removed | Bug found in a real textbook run: my first regex matched LaTeX *text* fonts, so every line was "math" and short code lines became equations. Tested on font names. |
| Monospace lines (font flag 8 or Courier/Mono/CMTT/...) are code, merged into listings, indentation rebuilt from x offsets; `code` lesson block with line-by-line English | The book is a Python programming book; code was being treated as equations. Mirrors codebase-to-course's code ↔ English block. Backticks are not accents. |
| Derivation fragments merged when lines are <= 16 pt apart on the same page | A real derivation was split into ~55 fragments so eq ids pointed at pieces. |
| ∑ ∫ √ ∂ ∇ no longer count as grounding evidence; ∆/Δ, ħ/¯h/ℏ unified; `checked_against: image` downgrades the symbol check to a warning | Real text layers turn ∑ into "X" and drop ∫; correct book formulas failed the check and had to be mislabelled `derived`. Trade-off: weaker automatic check, so the image check is the model's declared responsibility and is reported. |
| Verbatim problems: 3+-letter words matched in order (>= 90%) instead of exact text; clean `shown` version must keep the words (>= 85%) | Garbled math in the text layer made exact matching force "…" everywhere. The raw text proves the problem is the book's; `shown` is what the learner reads. |
| Citations: any page of a cited chapter is allowed (warning outside `source_refs.pages`), `read_full` pages count; other chapters are errors | A real run had to widen outline ranges by hand for two lessons; the original rule was stricter than the grounding goal needs. |
| Small sources (<= 1.35 x budget) get complete packs; gap markers list pages and distinctive words | Real run: packs dropped key paragraphs and only `needs_more` caught it. Complete packs remove the problem when the source is small; hints make remaining gaps visible. |
| Running heads: first/last two page lines count as candidates; a digit-bearing line is a header only if its number follows the page index (>= 2 pages) or it repeats on >= 40% of pages | Real run removed 0 header lines (headers outside the 9% band, number in a separate text run). First attempt also removed "Chapter N" labels (caught by existing tests), hence the page-index consistency test. |
| `pagemap` joins spans of a line with a space; `find` + `--anchor` for books without bookmarks or readable numbers | Real run: outline empty and pagemap failed; the user found pages by hand (+8 offset). |
| Dark theme = token overrides (`:root[data-theme=dark]` + `prefers-color-scheme` when no explicit choice), generated from one Python dict | styles.css is copied verbatim and already uses CSS variables; no edits to it. One source avoids the two blocks drifting apart. |
| Separate `--color-accent-text`; accent fills darkened until white text reaches 4.6:1 | Measured: no single accent value passes contrast both as text on dark and as a fill under white text; four of five palettes (including light-theme ones inherited from codebase-to-course) were at 4.1-4.3:1. Contrast is a test, not a guess. |
| Theme toggle is a button with `aria-pressed` and a fixed label | A label that flips together with a pressed state is announced wrongly by screen readers. |
| Contents = drawer on every screen size, Home = cover page (not a `.module`) | One pattern to test; main.js indexes `.module` elements for nav dots and arrow keys, so the cover must not be one. A capture-phase handler fixes the two keys main.js gets wrong with a cover (↓ from the cover, ↑ from module 1) and blocks arrows while the drawer is open. |
| Nav dots lose `role="tab"` (now a labelled group) | They had no tabpanels; ARIA tabs without panels are misleading. |
| UI code is plain JavaScript (no TypeScript/Bun build) | ~200 lines, no dependencies, must run from `file://` as a classic script; a build step would add a toolchain for no user benefit. If type checking is wanted: JSDoc + `// @ts-check` needs no build. |

## Browser JS lives in assets/ and is type-checked with JSDoc
UI and KaTeX glue moved from Python strings to `assets/book-ui.js` / `book-math.js` (render copies them unchanged). Reason: user request to add `// @ts-check`; checkers can't see JS inside Python strings. No TypeScript/Bun build, so `index.html` still opens from `file://`. `make typecheck-js` is the gate. Found while typing: `window.katex` must be looked up lazily (CDN script may load later).
